# Google Sheets row state

Version 1.0.0, bound to the pinned native runtime commit. Source: our own business construction; the fields and native routes come from the runtime's public interface implementation, and no released task answer is used.

Use this when a business field must be written into one identified row of a sheet while the other fields of that row are preserved. Contract approval ledgers, customer renewal lists, training registrations and ticket trackers can all reuse this row-state capability; the Author decides the business condition, the target row and the follow-up action. Google Sheets is the second most frequently scored application in the pinned reference distribution (about a third of tasks), and before this version no admitted asset could write sheet state.

The inputs are `business_context`, `spreadsheet_title`, `worksheet_title`, `headers`, `row_key`, `cells`, `protected_fields` and `protected_values`. `headers` holds 2 to 60 distinct header names; `row_key` must be one of them; `cells` maps the fields being written to their values and every key must come from `headers`; `protected_fields` must be non-empty, disjoint from `cells`, and each entry must have the asset's own initial value in `protected_values`. A protected field without an initial value, a write that collides with a protection, and an undeclared header all fail closed.

From the fixed task identity, seed and business time the constructor derives native IDs for the spreadsheet, worksheet and row, treats `row_key` as the stable row identity, seeds the protected cells' real initial values into that row, and sets **every cell to be written to the explicit placeholder `unset`**; if the Author's target value happens to equal that placeholder, construction is rejected. This makes each scored cell assertion a **necessary effect of the agent's own write** rather than points given away because the initial value already satisfied it. A native rows update merges, so a correct solution must write the target cells and must not disturb the protected cells. The constructor emits a field-level `google_sheets_row_cell_equals` for every written or protected cell (falling back to `google_sheets_cell_equals` where the first is unavailable, and rejecting construction if neither exists). It returns an independent world fragment, the entity mapping, a read entry point (`spreadsheets.values.get`) and the write action (`spreadsheets.values.update`). The same parameters replay, and no mutable state is shared between tasks.

The row identity is read-only and stable: `scored_row_state` requires the written cells to carry the Author's value on the target row; `protected_sibling_state` requires the protected cells to keep the asset's initial values; `stable_row_identity` requires scoring to stay bound to the same `row_key`, so a solution cannot evade it by changing rows or creating a new sheet. Read order, legal parallelism and legal alternative paths do not affect a correct solution, but a wrong row, wrong column, wrong value or damage to a protected cell must make scoring reject. The constructor does not generate a complete task and does not pick the business goal or final deliverable for the Author.

The minimum functional examples cover four contexts, each constructed in its own independent business scenario: correctly writing the target row while protecting the sibling fields; writing the wrong value into the target cell and failing scoring; damaging a protected cell and failing scoring; and writing nothing at all and failing scoring. A complete task still requires an independent semantic review.
